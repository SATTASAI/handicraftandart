# ศิลปหัตถกรรม

ระบบแข่งขันสำหรับ **ศูนย์เครือข่ายสองพี่น้อง ห้วยแม่เพรียง ป่าเด็ง** โรงเรียนบ้านป่าเด็ง สพป.เพชรบุรี เขต 2

## ฟังก์ชัน

- หน้าแรกเป็นการ์ดภาพปก ค้นหาและกรองรายการได้ กดการ์ดเพื่อดูเกณฑ์ วันเวลา สถานที่ และสมัคร
- สมัครบัญชี: ชื่อ–นามสกุล **สมัครเป็นกรรมการหรือผู้ฝึกซ้อม (เลือกหนึ่งบทบาท)** **โรงเรียนที่สังกัด** อีเมล และรหัสผ่าน โรงเรียนถูกบันทึกในฐานข้อมูลและแนบกับรายการสมัครจากฝั่งเซิร์ฟเวอร์
- เข้าสู่ระบบ ออกจากระบบ และลืมรหัสผ่านผ่าน **Resend** (ลิงก์ครั้งเดียว อายุ 30 นาที)
- ลงทะเบียนนักเรียนและครูผู้ฝึกซ้อม บันทึกร่าง ตรวจสอบ และยืนยัน พร้อมลิงก์ผลงาน HTTPS
- กรรมการเห็นและให้คะแนนได้เฉพาะรายการที่มอบหมาย
- ผู้ดูแลกำหนดสิทธิ์ มอบหมายกรรมการ แก้เกณฑ์/เวลา/สถานที่ เปิด–ปิดรับสมัคร และประกาศผล
- คะแนนเฉลี่ยจากกรรมการทุกคน แสดงผลหลังประกาศ และล็อกการแก้คะแนน
- ประกาศนียบัตร PDF ภาษาไทย แยกหน้าสำหรับนักเรียนและครู ดาวน์โหลดได้เฉพาะเจ้าของรายการ/ผู้ดูแลหลังยืนยันผล

รายการแข่งขัน จำนวนคน เกณฑ์คะแนน และช่วงรางวัลเริ่มต้นเป็น **ข้อมูลตัวอย่าง** ต้องยืนยันตามระเบียบการแข่งขันจริงก่อนใช้งาน เกณฑ์ตัวอย่าง: คุณภาพ 40 / ความคิดสร้างสรรค์ 30 / กระบวนการ 20 / นำเสนอ 10; ทอง 80 ขึ้นไป เงิน 70–79.99 ทองแดง 60–69.99 ให้แก้ `src/App.jsx`, `server/index.js`, `server/security.js` และ tests ให้ตรงกันหากเปลี่ยนเกณฑ์ ปรับจำนวนคน/รายการเพิ่มเติมใน D1 ตามข้อกำหนดจริง

## เทคโนโลยีและการติดตั้ง

React + Vite, Cloudflare **Workers with Static Assets**, D1, Resend REST API ไม่ใช่การอัปโหลดเฉพาะไฟล์ static ไป Cloudflare Pages เพราะระบบบัญชีต้องใช้ Worker และ D1

ใช้ Node.js 22 หรือใหม่กว่า:

```sh
npm ci
npm test
npm run build
```

### ทดลองในเครื่อง

```sh
cp .dev.vars.example .dev.vars
```

เปลี่ยน `AUTH_SECRET` เป็นค่าสุ่มอย่างน้อย 32 ตัวอักษร (เช่นสร้างด้วย `openssl rand -hex 32`) แล้วเปิด:

```sh
npm run dev -- --host 0.0.0.0 --port 4173
```

Vite โหลด Worker และ D1 จำลองผ่าน Miniflare ในกระบวนการเดียวกัน อัปเดต schema ให้อัตโนมัติ ข้อมูลอยู่ใน `.wrangler/vite-api/` และไม่ส่งขึ้น Git ต้องเริ่ม dev server ใหม่เมื่อแก้ `server/` หรือ migrations

อีกวิธีคือ `npm run db:local` แล้ว `npm run dev:full` เพื่อใช้ Wrangler + build assets ที่พอร์ต 8787 วิธีนี้ใช้ฐานข้อมูล local คนละชุดกับ Vite

### ตั้งค่า Cloudflare จริง

1. เชื่อมบัญชี Cloudflare ด้วย `npx wrangler login` หรือใช้ API token จาก secret store ของระบบ build
2. ใช้ D1 ที่มีอยู่แล้วชื่อ `handicraftandart` และตรวจสอบ UUID:

```sh
npx wrangler d1 info handicraftandart
```

3. นำ UUID ของฐานข้อมูล `handicraftandart` จากคำสั่งไปแทน UUID ตัวอย่างใน `wrangler.jsonc` โดยคง binding ชื่อ `DB`
4. กำหนด `SITE_URL` เป็น URL HTTPS จริงของเว็บ (เช่น Worker URL หรือ custom domain), `MAIL_FROM` เป็นชื่อ/อีเมลบนโดเมนที่ยืนยันใน Resend
5. ตั้งค่า secrets ผ่าน prompt ของ Wrangler ห้ามใส่ค่า secret ในโค้ดหรือ `VITE_*`:

```sh
npx wrangler secret put AUTH_SECRET
npx wrangler secret put RESEND_API_KEY
```

6. ใช้ฐานข้อมูล remote และ deploy:

```sh
npm run db:remote
npm run deploy
```

เมื่อเชื่อม GitHub ผ่าน Cloudflare Workers Builds: build command `npm ci && npm run build`, deploy command `npx wrangler deploy` และตั้ง D1/Secrets ให้ครบก่อน build แรก การ push รีโปเพียงอย่างเดียวไม่ได้สร้าง D1 หรือเผยแพร่เว็บอัตโนมัติหากยังไม่ได้เชื่อม Workers Builds

### ผู้ดูแลคนแรก

Migration `0004_initial_admin.sql` ตั้งสิทธิ์ Admin ให้บัญชีเดิม `sattawat.imc@gmail.com` ตามการอนุมัติของเจ้าของระบบ เมื่อ Cloudflare รัน `npm run db:remote` ระหว่าง deploy ไม่เปลี่ยนรหัสผ่านหรือข้อมูลโรงเรียน และไม่สร้างบัญชีใหม่

หลัง deploy ตรวจ `/api/health`: `adminSetupComplete: true` หมายถึงบัญชีเป้าหมายมีอยู่และเป็น Admin แล้ว Endpoint แสดงเฉพาะสถานะ boolean ไม่คืนอีเมล รหัสผ่าน หรือ Secret

หากยังไม่มีบัญชีเป้าหมาย การตั้ง Admin จะไม่เกิดขึ้น ต้องสมัครบัญชีให้เรียบร้อยก่อนดำเนินการ migration ตั้งสิทธิ์เพิ่มเติม ห้ามเพิ่มเงื่อนไขยกสิทธิ์อัตโนมัติในหน้า register หรือยกสิทธิ์ผู้สมัครคนแรก หลังมี Admin แล้วกำหนดกรรมการ/ผู้ดูแลผ่านเมนูจัดการสิทธิ์ได้

### Resend สำหรับลืมรหัสผ่าน

1. เพิ่มโดเมนหรือ subdomain สำหรับส่งอีเมลใน Resend แล้วเพิ่ม DNS DKIM/SPF ตามที่ Resend แสดง แนะนำ DMARC ตามนโยบายโดเมน ตรวจให้สถานะโดเมนเป็น Verified
2. สร้าง API key แบบ Sending access จำกัดโดเมนที่ใช้ และเก็บใน Cloudflare Secret `RESEND_API_KEY`
3. ตั้ง `MAIL_FROM` เช่น `ศิลปหัตถกรรม <support@mail.your-domain.example>` โดยต้องใช้โดเมนที่ยืนยันแล้ว ตั้ง `SITE_URL` เป็น URL HTTPS จริงของเว็บ
4. กดลืมรหัสผ่านด้วยบัญชีทดสอบที่คุณเป็นเจ้าของ ตรวจส่งถึง inbox/spam และทดสอบลิงก์ใช้แล้วเปิดซ้ำไม่ได้

หากยังไม่ตั้งอีเมล ระบบจะแจ้งว่าผู้ดูแลยังไม่ได้ตั้งค่า ไม่แสดงว่าส่งสำเร็จ API ไม่เปิดเผยว่ามีอีเมลอยู่ในระบบหรือไม่ หาก provider ส่งไม่สำเร็จจะลบ token ที่ส่งไม่ได้และบันทึกเฉพาะข้อความ error ทั่วไปโดยไม่บันทึกรหัสผ่าน/ลิงก์รีเซ็ต

ในการพัฒนานี้ทดสอบ Resend ด้วยตัวจำลอง HTTP ไม่ส่งอีเมลจริง และยังไม่ได้ตั้งโดเมน, API key, D1 หรือ deploy ในบัญชี Cloudflare จริง

### ก่อนเปิดรับสมัครจริง

ยืนยันรายการแข่งขันและเกณฑ์กับผู้จัด แก้วันเวลา/สถานที่/รายละเอียดผ่านผู้ดูแล ตรวจ PDF และข้อมูลผู้ออกประกาศนียบัตรให้ตรงข้อกำหนดจริง แล้วเปลี่ยน `DEMO_MODE` เป็น `"false"` ใน `wrangler.jsonc` และ deploy ใหม่ ประกาศนียบัตรตัวอย่างไม่มีลายเซ็นหรือตราราชการที่สมมติขึ้น

ข้อมูลโรงเรียนเป็นข้อมูลที่ครูระบุตอนสมัคร ยังไม่มีขั้นตอนตรวจสอบหลักฐานสังกัดหรือยืนยันอีเมล เก็บลิงก์ผลงานภายนอก ไม่มีระบบอัปโหลดไฟล์ลง R2 ในรุ่นนี้

## โครงสร้าง

- `src/` หน้าเว็บและ PDF renderer
- `server/index.js` API, sessions, สิทธิ์, Resend และผลการแข่งขัน
- `server/security.js` PBKDF2-SHA256 + server pepper, token hashing, validation
- `migrations/` schema D1 และข้อมูลแข่งขันตัวอย่าง
- `public/covers/` ภาพปก WebP ที่สร้างสำหรับงานนี้
- `public/fonts/` Noto Sans Thai รวมชุด Thai/Latin สำหรับ PDF พร้อม OFL license
- `tests/` ทดสอบ Worker/D1 จริงใน Miniflare, auth/reset/role/scoring/certificate และ PDF
- `qa/`, `design-qa.md` หลักฐานตรวจหน้าจอ
- `worker/` และ `scripts/prepare-sites-build.mjs` คงไว้สำหรับ runtime ของ Product Design; production Cloudflare ใช้ `server/index.js` ตาม `wrangler.jsonc`

## ความปลอดภัย

Session cookies เป็น HttpOnly, SameSite=Lax และ Secure บน HTTPS; บังคับ same-origin สำหรับทุก mutation; password ใช้ random salt และ pepper จาก AUTH_SECRET; session/reset tokens เก็บเฉพาะ SHA-256; rate limit ตาม IP และอีเมล; เปลี่ยนรหัสผ่านแล้วเพิกถอนทุก session; ตรวจ ownership และ role ฝั่งเซิร์ฟเวอร์ ไม่เชื่อโรงเรียนหรือคะแนนรวมจาก client

PBKDF2 ใช้ 100,000 รอบตามข้อจำกัดที่รองรับใน Workers ร่วมกับ server pepper และ rate limit เก็บ AUTH_SECRET ให้ปลอดภัยและคงเดิม ไม่เช่นนั้นรหัสผ่านเดิมจะใช้ไม่ได้ จัด retention/cleanup ตาราง sessions, resets และ throttle ตามนโยบายผู้จัดก่อนใช้งานระยะยาว

### ข้อมูลบทบาทตอนสมัคร

Migration `0005_applicant_roles.sql` เพิ่ม `users.applicant_role` แยกจากสิทธิ์จริง (`users.role`) ผู้สมัครต้องเลือก `judge` หรือ `coach` เพียงค่าเดียว ทุกบัญชีใหม่ยังเริ่มด้วยสิทธิ์ `participant` จน Admin กำหนดสิทธิ์ บัญชีเดิมไม่ถูกคาดเดาบทบาทย้อนหลังและแสดง “ไม่ระบุ (บัญชีเดิม)” ในหน้าจัดการสิทธิ์ หน้านี้แสดงชื่อ อีเมล โรงเรียน บทบาทที่สมัคร วันที่สมัคร (เวลาไทย) และสิทธิ์ใช้งานจริง โดย API ยังคงอนุญาตเฉพาะ Admin

หน้าเข้าสู่ระบบอยู่ที่ `/login` พร้อมหน้า `/signup` และ `/forgot-password` ใช้ API บัญชีเดิม เมื่อเปิดจากรายการแข่งขันจะกลับไปลงทะเบียนรายการนั้นหลังเข้าสู่ระบบสำเร็จ

ทุกหน้าการแข่งขันต้องเข้าสู่ระบบก่อน ผู้ที่ยังไม่เข้าสู่ระบบถูกส่งไป `/login` และไม่แสดงเมนูหลัก หน้าสมัครสมาชิกและกู้รหัสผ่านยังเปิดได้ ส่วน API รายการแข่งขันและผลการแข่งขันต้องมี session ที่ยังไม่หมดอายุ

## การจัดงานปีการศึกษา 2569

ชื่องาน: **งานศิลปหัตถกรรม ศูนย์เครือข่ายสองพี่น้อง ห้วยแม่เพรียง ป่าเด็ง ประจำปีการศึกษา 2569**

เมนูผู้ดูแล → **ภาพรวม / ผู้สมัคร / ส่งประกาศนียบัตร** แสดงจำนวนทีมที่ยืนยัน จำนวนกรรมการ และจำนวนคะแนนที่บันทึกเทียบกับที่ต้องมี พร้อมรายชื่อผู้สมัครและส่งออก CSV (UTF-8 สำหรับ Excel และป้องกันสูตรจากข้อมูลผู้สมัคร) คะแนนครบหมายถึงพร้อมให้ผู้จัดตรวจสอบ ไม่ได้ยืนยันว่าเกณฑ์ตัวอย่างเป็นเกณฑ์ทางการ

หลังประกาศผล กด **ส่งลิงก์ทางอีเมล** รายทีม ระบบส่งถึงอีเมลของบัญชีผู้ลงทะเบียน ให้เข้าสู่ระบบที่ `/certificates` เพื่อดาวน์โหลด PDF นักเรียนและครู ไม่แนบข้อมูลนักเรียนหรือ token เข้าสู่ระบบในลิงก์ สถานะ “ส่งให้บริการอีเมลแล้ว” หมายถึง Resend รับคำขอ ต้องตรวจ delivered/bounced ใน Resend แยกต่างหาก รุ่นนี้ยังไม่มี webhook ยืนยันการส่งถึง

การกดพร้อมกันใช้ฐานข้อมูลล็อกการส่ง และใช้ Resend idempotency key เดิมเมื่อส่งซ้ำ หากขัดข้องลองใหม่ภายใน **23 ชั่วโมงนับจากครั้งแรก** (รออย่างน้อย 90 วินาทีเมื่อคำขอเดิมค้าง) หากเกินช่วงนี้ ระบบจะหยุดส่งซ้ำเพื่อป้องกันอีเมลซ้ำหลัง provider ลืม key ให้ตรวจประวัติ Resend และติดต่อผู้รับโดยตรง ระบบไม่ส่งอัตโนมัติตอนประกาศผล

### อัปเดตระบบเดิม

1. สำรอง D1 ก่อนอัปเดต: `npx wrangler d1 export handicraftandart --remote --output /path/to/secure-backup.sql` เก็บไฟล์ไว้นอก Git เพราะมีข้อมูลบัญชีและผู้สมัคร
2. รัน `npm ci`, `npm test`, `npm run build`, `npm run test:sites`
3. ใช้บัญชี Cloudflare ของเว็บเดิม รัน `npm run db:remote` เพื่อเพิ่ม migration `0006_certificate_deliveries.sql` ซึ่งเพิ่มตารางใหม่ ไม่ลบข้อมูลเดิม แล้ว `npm run deploy`
4. ผู้ดูแลตรวจหน้าภาพรวม ตั้งค่า `AUTH_SECRET` เดิม (ห้ามเปลี่ยนโดยไม่วางแผน), `RESEND_API_KEY`, `MAIL_FROM`, `SITE_URL` และทดสอบส่งถึงบัญชีที่ผู้จัดเป็นเจ้าของ
5. ยืนยันวันแข่งขัน สถานที่ รายการแข่งขัน จำนวนคน เกณฑ์คะแนน/รางวัล และข้อมูลผู้ออกประกาศนียบัตรก่อนตั้ง `DEMO_MODE=false` ข้อมูลที่ยังไม่ยืนยันต้องไม่ถือเป็นประกาศทางการ

การทดสอบอัตโนมัติใช้ D1/Worker จำลองจริงและ Resend HTTP จำลอง ครอบคลุมสิทธิ์ผู้ดูแล การห้ามส่งก่อนประกาศผล การส่งล้มเหลวแล้วลองใหม่ การส่งพร้อมกัน การไม่ส่งซ้ำ และการหยุด retry เกินช่วงปลอดภัย ไม่ได้ยืนยันการรับอีเมลจริงหรือการ deploy ไปบัญชี Cloudflare

## ชุดทดสอบเกณฑ์ปี 2568 ครบระดับประถม

นำเข้า **197 รายการย่อย**: ทั่วไป 50 / เรียนรวม 27 / โรงเรียนเฉพาะความพิการ 82 / ศูนย์การศึกษาพิเศษอายุ 7–12 ปี 38 รายการ ดู [บัญชีรายการ แหล่งอ้างอิง และข้อจำกัด](docs/criteria-2568.md)

Migration `0007` เพิ่มตัวอย่างตรวจเกณฑ์ 4 รายการ และ `0008` เพิ่มชุดเต็มโดยแยกรหัส พร้อมปิดตัวอย่างเก่าที่ไม่มีข้อมูล ไม่ลบผู้สมัครหรือคะแนนเดิม หน้าแรกกรองประเภทสถานศึกษาและช่วงชั้นได้ แสดงครั้งละ 24 รายการ เปิด “รวมรายการตัวอย่างเดิม” เมื่อต้องดูรายการเก่า

ผู้จัดต้องตรวจคุณสมบัติในภาพรวมก่อนประกาศผล ระบบกันกรรมการบัญชีเจ้าของทีมและโรงเรียนเดียวกัน นับจำนวนคะแนนที่ต้องมีจากกรรมการที่ไม่มีส่วนได้เสียรายทีม หากจำนวนไม่ตรงเกณฑ์จะประกาศผลไม่ได้ กรณีตัดสิทธิ์ต้องมีเหตุผลและไม่ออกประกาศนียบัตร

คะแนนเต็มดิบเป็นไปตามรายการ เช่น 20 หรือ 100 จากนั้นแปลงเป็นร้อยละก่อนเฉลี่ย คะแนนหักต้องระบุเหตุผล ผู้จัดยังต้องดำเนินการตรวจเอกสาร คุณวุฒิกรรมการ บทบาทกรรมการเฉพาะด้าน และข้อชี้ขาดตามต้นฉบับก่อนยืนยันผล

แก้เกณฑ์และคุณสมบัติผ่านเมนูจัดการรายการได้ก่อนมีทีมยืนยันสมัคร หลังจากนั้นใช้ “สร้างฉบับใหม่” ระบบจะคัดลอกเป็นรายการที่ยังปิดรับสมัครให้แก้ไข โดยไม่กระทบข้อมูลเดิม

เมื่ออัปเดต ให้สำรองฐานข้อมูลแล้วใช้ `npm run db:remote` ก่อน deploy เพื่อเพิ่ม migrations ทั้งสองฉบับ พร้อมตรวจ `/api/health` ว่า release เป็น `primary-criteria-2568-trial` และทดลองด้วยบัญชีผู้จัด

ระบบ dev ใช้ `resourcePersistencePath` ของ Miniflare v5 เก็บ D1 และค่าสุ่มสำหรับทดสอบไว้ใต้ `.wrangler/vite-api/` หรือ `.wrangler/local-api/` ที่ไม่เข้า Git รหัสผ่านจึงใช้ต่อได้เมื่อเริ่ม dev ใหม่ หากเคยใช้ตัวจำลองรุ่นที่ไม่บันทึกข้อมูล ต้องสร้างบัญชีทดสอบใหม่ ไม่มีผลต่อ D1 จริง
