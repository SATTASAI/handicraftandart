# Current product requirements

This is a fresh account system after the owner deleted the old app. Latest instructions override prior historical requirements.

- Signup requires full name, school, email, password and at least one role: coach (ผู้ฝึกซ้อม), judge (กรรมการ), or both. Roles use independent checkboxes.
- The first successfully registered account is superadmin with access to all functionality. This is explicitly requested by the owner; do not change this to manual approval or disable it.
- Allocate first-account privilege only on the server in one atomic D1 batch with the permanent account_bootstrap marker and unique superadmin index. Subsequent signups must never gain superadmin via request parameters. Never reset the marker during ordinary startup or deployment.
- All privileged routes must check the authenticated session on the server. Superadmin has all permissions. No client-only access checks.
- Use real Cloudflare D1 and opaque HttpOnly session cookies. Never store plaintext passwords, localStorage authentication, credentials or synthetic accounts in Git.
- Thai interface, compact blue/white header, pale-blue welcome panel, responsive forms.
- Current milestone also includes competition creation, coach-submitted student registration with ID-card images, and organizer/superadmin review. See docs/competition-registration.md.
- D1 binding DB targets the existing handicraftandart database. Migration 0011 creates fresh account_* tables without importing old accounts or deleting old competition tables. The earlier remote database reset is still unperformed. Do not use the prior destructive SQL in /workspace/scratch as an account migration.
- Dev: npm ci; npm run dev (port 4173), local persistence .wrangler/accounts-v1. Validate with npm test; npm run build; npx wrangler deploy --dry-run --outdir .wrangler/deploy-check.
- No automatic production migration/build hook is included. Production migration and deployment require separate authorization; do not push to a deployment branch as part of local validation.

- Owner added organizer (ผู้จัด) document-review authority. Only superadmin may assign/revoke organizer on existing accounts; public signup remains coach/judge/both. Organizer may inspect submitted documents and approve/return registrations, but cannot grant roles or review their own team. Superadmin retains all permissions.
- Migration 0012 is additive: preserve existing accounts, passwords, sessions and bootstrap marker. Registration and reviewer authorization must be enforced by the API. Approved teams are read-only for coaches; edits before approval increment revision and return to pending. Reviews must match the current revision to prevent approving stale data.
- Student fields are separate first name, last name, grade and school; each requires a private JPEG/PNG ID image. Never add real identity evidence or synthetic accounts to Git. Documents must be served via authenticated, no-store API with owner/reviewer checks, never public assets. Organizers cannot read orphan uploads. Keep per-image API limit at 1 MB.
- Default local D1 remains .wrangler/accounts-v1; LOCAL_D1_PATH is only a non-secret local testing override. Browser QA must use isolated local data and synthetic ID images, preserving the normal dev database and all production accounts.

- Owner provided 10 PDF rule files and approved primary-only scope (ป.1–6, including relevant inclusive/special education) plus using the attached 73/2568 rules and opening imported registration immediately. Import only exact verified supplied sources; do not restore the old 197-entry catalog or invent unsupported eligibility/limits/current-year dates.
- Audited import count is 76: general 49 + inclusive 27. The preliminary 77 split the 7-person Sawasdi exception into a separate event; preserve it as a routine variant of the same Thai classical dance competition. Source PDFs and source/section/event keys are hash-versioned. See docs/criteria-73-import.md.
- Migration 0013 must remain additive and preserve all existing IDs, registrations, private documents, accounts and bootstrap marker. Canonical counts are roster_min_students/roster_max_students when roster_min is non-null, otherwise use legacy min/max. A null canonical maximum is unspecified, not an invented upper limit. Keep SQL write guards aligned with effective counts.
- Keep source score tables/readable original PDFs available after login. All assets pass through the Worker so PDF originals cannot bypass auth; card previews are paginated. Imported film registration requires five students, two coach names and HTTPS work URL. Imported grade/gender/routine-variant rules are checked on the server.
- Inclusive medical/IEP eligibility evidence is not newly stored in this milestone; organizers must inspect the additional documents outside the app before confirming. Do not claim the student ID alone proves disability eligibility.

- Judging milestone (docs/judging-results.md): superadmin assigns judge-role accounts per competition; judges score approved teams per criterion (fallback single 100-point criterion); a judge never scores own team. Team score = average of required judges' totals at the current revision. Medals: gold >=80, silver >=70, bronze >=60 (percent of max), else participation; ranks 1-3 labelled. Results auto-publish when every team is fully scored; before that only organizer/superadmin see progress. Certificates (one PDF page per student, generated client-side) are visible only for the coach's own teams (superadmin: all); superadmin edits certificate settings. After a competition publishes results: coaches also download a coach (ครูผู้ฝึกซ้อม) certificate per own team (one page per listed coach name, team medal); assigned judges download their own judge (กรรมการตัดสิน) certificate plus student certificates of every team in that competition, but not other teams' coach certificates. Migration 0014 is additive.

- Forgot password (migration 0015, additive): POST /api/password/forgot emails a single-use reset link via Resend (secret RESEND_API_KEY; optional RESEND_FROM, default no-reply@mail.banpadengschool.ac.th). Response is identical whether the email exists; mail is sent via waitUntil. Link uses URL fragment /reset-password#token=…, valid 30 minutes; only the SHA-256 token hash is stored. POST /api/password/reset sets the new password (12–128 chars), deletes all reset tokens and all sessions of that user. Never commit the Resend key.

- Google Drive storage (migration 0016, additive; docs/google-drive-storage.md): when secrets GOOGLE_CLIENT_ID/GOOGLE_CLIENT_SECRET/GOOGLE_REFRESH_TOKEN (scope drive.file, dedicated account) are set, new ID-card images are stored in Drive (row keeps metadata, empty data blob, drive_file_id) and still served only via the authenticated no-store API; Drive copies are deleted with their rows. Superadmin migrates old D1 images in batches of 10 (POST /api/admin/storage/migrate). Certificate PDFs are cached per unit (student/coach per team, judge per person) in certificate_files keyed by a server fingerprint of printed data + settings + CERTIFICATE_DESIGN; bump CERTIFICATE_DESIGN in server/judging.js whenever certificatePdf.js drawing changes. Without the secrets everything falls back to D1 / client-side generation. Never commit Google credentials.

- Trash and portal content (migration 0018, additive): superadmin deletes of competitions, teams, scores and accounts send confirm "ถังขยะ" and are kept in admin_trash as JSON snapshots (restore or purge at /api/admin/console/trash); confirm "ลบถาวร" still deletes immediately. ID images of trashed teams/accounts stay stored (a trashed account's images are held by the deleting superadmin) until purge; keep docNotInTrash on every orphan-document cleanup. Restores insert one statement per table (D1 query limit). Round reset / data reset drop trashed teams and scores. Home-page text, countdown and news live in app_settings key portal_content (survives a new round), edited at /api/admin/console/portal and returned by /api/portal.

- Passkeys and login security (migration 0019, additive, new tables only): any account may register passkeys (Face ID / fingerprint) at /api/passkey/register and sign in without a password at /api/passkey/login; verification is hand-written WebCrypto in server/security.js (ES256/RS256, user verification required, single-use 5-minute challenges, rpId = request hostname) — no npm dependency. Eight wrong passwords pause that email for 15 minutes (passkey and password reset still work). account_session_info records device/IP per session for /api/sessions (list, revoke others); never ALTER account_sessions. account_login_log keeps 90 days for superadmin (/api/admin/console/logins). Cloudflare Turnstile guards login, signup and forgot-password only when both TURNSTILE_SITE_KEY and TURNSTILE_SECRET_KEY are set; never commit them.

- Workspace theme (owner request, overrides the earlier "compact blue/white header"): /workspace and the signup/reset screens follow the public portal's look — Prompt font, white 60px header with the portal logo, navy/indigo palette, gradient pill buttons, soft-shadow cards — through the "Portal theme" block at the end of src/styles.css. Night mode toggles `dark-mode` on <html> and shares the portal's localStorage key `arts-network-portal-dark`; use the CSS variables (--white, --control, --line…) instead of literal colours in new rules so both modes work.

- Home banner (ครั้งที่ 74): public/portal/media/banner74 holds a text-free background (base.webp, text inpainted out) plus transparent text layers cut from the owner's banner; positions and entrance/sparkle animations live in public/portal/banner.css (CSP forbids inline style attributes). To change the banner, regenerate all layers from the new image together.
