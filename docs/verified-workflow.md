# ขั้นตอนบัญชีและการแข่งขัน

## โรงเรียน

สมัครประเภท “บัญชีโรงเรียน / ผู้ฝึกซ้อม” พร้อมภาพบัตรของผู้สมัครบัญชี แล้วรอแอดมินตรวจยืนยัน เมื่อตรวจผ่านจึงเลือกรายการแข่งขัน กรอกชื่อ ชั้น โรงเรียน และครูผู้ฝึกซ้อม พร้อมภาพบัตรของผู้แข่งขันและครูแต่ละคน (ครูคนเดียวกับเจ้าของบัญชีใช้หลักฐานบัญชีได้)

ตรวจทานแล้วกดยืนยันส่งให้แอดมินตรวจทีม ข้อมูลทีมที่แก้ไขจะกลับไปรอตรวจใหม่ โรงเรียนจากบัญชีถูกผูกกับทีมฝั่งเซิร์ฟเวอร์ จึงเปลี่ยนโรงเรียนด้วยการแก้ payload ไม่ได้

กำหนดเวลาทั้งงานใช้เวลาไทย UTC+7: เปิดรับสมัคร < ปิดรับสมัคร ≤ ปิดแก้ไข เมื่อปิดสมัครจะรับทีมใหม่ไม่ได้ แต่ทีมที่ยืนยันแล้วแก้ไขได้ก่อนปิดแก้ไข แอดมินกำหนดจากหน้าภาพรวม หากยังไม่ตั้งเวลา ระบบยังไม่รับสมัครในขั้นตอนใหม่

## กรรมการ

สมัครประเภทกรรมการ แนบภาพบัตร และรอแอดมินยืนยัน แอดมินเลือกได้จากบัญชีที่ยืนยันแล้วและไม่มีโรงเรียนตนเองเข้าร่วมการแข่งขันทั้งรายการ ปุ่มคัดเลือกอัตโนมัติเลือกให้ครบจำนวนขั้นต่ำที่เกณฑ์ยอมรับ โดยเรียงตามภาระงานก่อน และผู้ดูแลตรวจคุณวุฒิจากเกณฑ์ต้นฉบับอีกครั้ง

หน้าแรกกรรมการแสดงเฉพาะรายการที่ได้รับมอบหมาย กดรายการเพื่อเปิดคะแนนตามเกณฑ์ปี 2568 เริ่มให้คะแนนได้หลังปิดแก้ไขข้อมูลและทีมผ่านการตรวจแล้ว มีทั้ง “บันทึกคะแนนร่าง” และ “ยืนยันผลการลงคะแนน”

ก่อนยืนยัน ระบบเตือนว่าคะแนนจะเป็นผลขั้นสุดท้ายและแก้ไขไม่ได้อีก หลังยืนยันจะล็อกทันที แม้กรรมการคนอื่นยังลงคะแนนไม่ครบ แอดมินถอนกรรมการที่ยืนยันคะแนนแล้วไม่ได้ และการเปลี่ยนข้อมูลทีมหลังมีคะแนนยืนยันถูกป้องกันฝั่งเซิร์ฟเวอร์

ถ้าโรงเรียนใหม่ลงทะเบียนเข้ารายการที่มีกรรมการโรงเรียนนั้นมอบหมายไว้ก่อน ระบบถอนการมอบหมายที่ขัดกันก่อนเริ่มการตัดสิน กรรมการที่ขัดกันจะไม่เห็นแม้แต่ทีมโรงเรียนอื่นในรายการนั้น

## ผลและประกาศนียบัตร

เมื่อทุกทีมผ่านการตรวจและกรรมการที่มีสิทธิ์ทุกคนยืนยันครบ ระบบสรุปคะแนนร้อยละและประกาศผลอัตโนมัติ ไม่ต้องรอกดประกาศผลเพิ่ม เรียงอันดับแยกแต่ละรายการ คะแนนเท่ากันใช้อันดับร่วมแบบ 1, 1, 3 และแสดงชนะเลิศ/รองชนะเลิศอันดับ 1/รองชนะเลิศอันดับ 2 สำหรับอันดับ 1–3

เมนูประกาศนียบัตรแสดงทีมที่บัญชีโรงเรียนลงทะเบียน เมื่อรายการเสร็จจะเปิดให้สร้างและดาวน์โหลด PDF ภาษาไทยได้ทันที แยกหน้าสำหรับนักเรียนกับครู พร้อมอันดับ/รางวัล กรณีตัดสิทธิ์จะไม่เปิด PDF คะแนนดิบเต็ม 20 หรือ 100 แปลงเป็นร้อยละก่อนเฉลี่ยตามระบบเดิม

## หลักฐานส่วนตัวและการอัปเดต

ภาพบัตรไม่อยู่ใน public assets และไม่มีลิงก์สาธารณะ เก็บเป็น BLOB ใน D1 เดิม เปิดได้เฉพาะเจ้าของกับแอดมินผ่าน session และใช้ `Cache-Control: private, no-store` กรรมการดูภาพบัตรนักเรียนไม่ได้ เบราว์เซอร์ย่อ JPEG/PNG ขนาดเกิน 1 MB (รับต้นฉบับไม่เกิน 10 MB) และเซิร์ฟเวอร์จำกัดไฟล์เก็บจริง 1 MB พร้อมตรวจชนิดไฟล์ ห้ามอัปโหลดเอกสารจริงเข้า Git

Migration `0009_verified_workflow.sql` เก็บข้อมูลและคะแนนเดิมไว้ ผลที่ประกาศแล้วเป็นประวัติเดิม รายการที่ยังไม่จบใช้ขั้นตอนใหม่ บัญชีที่ไม่ใช่แอดมินกลับมารอตรวจหลักฐาน ก่อนเริ่มแอดมินต้องตั้งช่วงเวลา เปิดโอกาสให้บัญชี/ทีมเดิมเติมหลักฐาน และตรวจการมอบหมายใหม่ กรรมการโรงเรียนเดียวกันในรายการที่ยังไม่จบจะถูกถอนออก ไม่เปลี่ยนผลที่ประกาศไปแล้ว

สำรอง D1 แบบส่วนตัวก่อน apply migration แล้วจึง deploy ไม่ต้องเพิ่ม R2 หรือ secret ใหม่ เพราะใช้ D1 และระบบ session เดิม ผู้จัดควรกำหนดระยะเวลาการเก็บและลบภาพบัตร รวมถึงติดตามขนาดฐานข้อมูลตามจำนวนผู้สมัครจริง
