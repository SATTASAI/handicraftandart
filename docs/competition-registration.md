# ลงทะเบียนแข่งขันและตรวจเอกสาร

## สิทธิ์

- ผู้ฝึกซ้อม: เลือกรายการ กรอกนักเรียน แนบภาพบัตร ส่งคำขอ และดู/แก้รายการของตนเองก่อนยืนยัน
- กรรมการที่ไม่มีบทบาทผู้ฝึกซ้อม: ดูรายการแข่งขันได้ แต่ส่งทีมและเปิดเอกสารนักเรียนไม่ได้
- ผู้จัด: ตรวจรายการที่ส่งแล้ว เปิดภาพบัตร ยืนยันลงทะเบียน หรือระบุหมายเหตุขอแก้ไข ไม่มีสิทธิ์มอบบทบาทหรือดูรายชื่อบัญชีทั้งหมด ผู้จัดไม่ยืนยันทีมที่ตัวเองส่ง (ให้ผู้จัดคนอื่นหรือ superadmin ตรวจ)
- superadmin: มีสิทธิ์ทั้งหมด เพิ่ม/เปิดปิดรายการแข่งขัน ตรวจเอกสาร และให้/ถอนสิทธิ์ผู้จัดแก่บัญชีที่มีอยู่

บทบาทผู้จัดไม่ได้เปิดให้เลือกเองในหน้าสมัคร ใช้ปุ่ม “มอบสิทธิ์ผู้จัด” บนหน้า dashboard แล้วเลือกช่อง “สิทธิ์ผู้จัดตรวจเอกสาร” ของผู้ใช้ ผู้ได้รับสิทธิ์รีเฟรชหน้าหรือเข้าสู่ระบบใหม่เพื่อแสดงเมนู การถอนสิทธิ์มีผลกับการเรียก API ครั้งถัดไป

## เริ่มใช้งาน

1. superadmin เพิ่มชื่อรายการ รายละเอียด ระดับชั้น จำนวนผู้แข่งขัน และวันเวลา/สถานที่ถ้ามี ใน “จัดการรายการแข่งขัน” ไม่สร้างรายการหรือวันแข่งขันสมมติให้อัตโนมัติ
2. ผู้ฝึกซ้อมเลือกรายการ กรอก **ชื่อ นามสกุล ชั้น โรงเรียน** แยกตามนักเรียนแต่ละคน และแนบภาพบัตรของแต่ละคน เพิ่มนักเรียนได้ภายในจำนวนที่กำหนด
3. กด “ส่งให้ผู้จัดตรวจสอบ” รายการเป็น **รอตรวจเอกสาร** การส่งซ้ำจาก request เดิมไม่สร้างทีมซ้ำ ครูส่งได้หลายทีมโดยเปิดฟอร์มใหม่ ไม่กำหนดข้อจำกัดจำนวนทีมต่อโรงเรียนโดยไม่มีระเบียบจากผู้จัด แต่นักเรียนคนเดียวกัน (ชื่อ นามสกุล โรงเรียนเดียวกัน) ลงซ้ำในรายการเดียวกันไม่ได้ แม้ส่งโดยครูคนละคน
4. ผู้จัดเปิด “ตรวจเอกสาร / ยืนยัน” กดดูข้อมูลและเอกสาร แล้ว “ยืนยันการลงทะเบียน” หรือ “ส่งกลับให้แก้ไข” พร้อมเหตุผล
5. ผู้ฝึกซ้อมดูผลใน “รายการสมัครของฉัน” ใช้ “อัปเดตข้อมูล” เพื่อตรวจสถานะล่าสุด แก้ไขแล้วต้องส่งเข้าคิวตรวจใหม่ เมื่อยืนยันแล้วจะไม่เปิดให้ครูแก้ข้อมูลเอง

### ลงทะเบียนด้วยไฟล์ xlsx

- หน้ารายการแข่งขันมีปุ่ม “ดาวน์โหลด template .xlsx” (ไฟล์กลางไฟล์เดียว สร้างในเบราว์เซอร์) 1 ไฟล์ = 1 ทีม: ครูผู้ฝึกซ้อม (ไม่เกิน 3), ลิงก์ผลงาน, ชุดการแสดง และตารางนักเรียน ลำดับ/ชื่อ/นามสกุล/ชั้น/เพศ/โรงเรียน (20 แถว)
- การ์ดแต่ละรายการมีปุ่ม “นำเข้า xlsx” อ่านแผ่นงานแรกในเบราว์เซอร์ (รองรับ Excel, Google Sheets, Numbers ที่บันทึกเป็น .xlsx ไม่เกิน 2 MB) แล้วเปิดฟอร์มลงทะเบียนพร้อมข้อมูล ไม่ส่งไฟล์ขึ้นเซิร์ฟเวอร์ ไฟล์ที่มีนักเรียนเกินจำนวนสูงสุดถูกปฏิเสธ ถ้าน้อยกว่าขั้นต่ำจะเติมแถวว่าง
- ชั้นแปลงเป็นรูป ป.1–ป.6 (เช่น 4, ประถมศึกษาปีที่ ๔) เพศรับ ชาย/หญิง/ช/ญ/ด.ช./ด.ญ. โรงเรียนว่างใช้โรงเรียนของผู้ฝึกซ้อม ชุดการแสดงจับคู่กับชื่อชุดในรายการ ไม่พบให้เลือกเอง
- **ภาพบัตรประชาชนยังแนบรายคนในฟอร์มเหมือนเดิม** ข้อมูลทั้งหมดผ่านการตรวจฝั่ง API ตามปกติเมื่อกดส่ง

รายการที่ปิดรับสมัครแล้วไม่รับคำขอหรือการแก้ข้อมูลใหม่ แต่ยังตรวจคำขอที่ส่งไว้แล้วได้ การกำหนดชั้นในรายการเป็นคำอธิบายให้ผู้จัดตรวจคุณสมบัติจริง ไม่ใช่การรับรองเกณฑ์ทางการโดยระบบ

## การเข้าสู่ระบบจากเครือข่ายเดียวกัน

ครูหลายคนในโรงเรียน/ที่ประชุมมักใช้ IP สาธารณะเดียวกัน จึงตั้ง rate limit ต่อ IP ไว้กว้าง (สมัคร 60 ครั้ง/ชม., เข้าสู่ระบบ 120 ครั้ง/15 นาที) และจำกัดต่ออีเมล 20 ครั้ง/15 นาทีเพื่อกันการเดารหัสผ่าน session และ rate-limit ที่หมดอายุถูกล้างเมื่อมีการเข้าสู่ระบบ

## ภาพบัตรประชาชน

รองรับ JPG/PNG ต้นฉบับไม่เกิน 10 MB หน้าเว็บจะวาดภาพใหม่เพื่อตัด metadata ปรับด้านยาวไม่เกิน 1600 px และส่ง JPG ไม่เกิน 1 MB ฝั่ง API ตรวจชนิดไฟล์จาก header/signature และจำกัดขนาดซ้ำ ผู้ส่งควรเปิดภาพเต็มตรวจความชัดเจนก่อนส่ง

ภาพเก็บเป็น BLOB ใน D1 แยกจาก public assets เปิดผ่าน API ที่ตรวจ session เท่านั้น ไม่ใช้ URL สาธารณะ ไม่ส่ง image bytes ในรายการข้อมูล ภาพและ API รายการสมัครตั้ง no-store ผู้ฝึกซ้อมเห็นเฉพาะภาพที่ตนส่ง ผู้จัดเห็นเฉพาะภาพที่ผูกกับรายการสมัครแล้ว superadmin เห็นได้ทั้งหมด

ภาพใหม่ที่ยังไม่ถูกใช้จะลบทิ้งเมื่อออกจากฟอร์มตามที่เบราว์เซอร์ส่งคำขอสำเร็จ และภาพที่ค้างไม่ถูกผูกเกิน 24 ชั่วโมงจะลบในครั้งถัดไปที่เจ้าของอัปโหลด ภาพที่ถูกใช้ในทีมจะไม่ลบผ่าน API ลบไฟล์ทั่วไป หากแก้ทีมเพื่อแทนภาพเก่า ภาพที่ไม่มีรายการอ้างอิงจะถูกลบพร้อมการบันทึกแก้ไข ภาพที่ส่งแล้วคงอยู่เพื่อให้ผู้จัดตรวจ ยังไม่มีระบบลบข้อมูลตามอายุงานหรือ export ข้อมูลส่วนตัวใน milestone นี้

## ฐานข้อมูล / ตรวจสอบ

Migration `0012_competition_registration.sql` เพิ่ม flag ผู้จัดและตารางการแข่งขัน เอกสาร รายการสมัคร นักเรียน และประวัติผลตรวจ โดยไม่ล้างบัญชี `account_users`, session, password หรือ marker superadmin เดิม

`/api/health` ต้องได้ `{ok:true, release:"registration-v1"}` และตรวจพบตาราง/สิทธิ์ใหม่แล้ว

`npm run deploy` ใช้ migrations ก่อน deploy ตามเดิม ไม่เพิ่ม production prebuild hook โค้ดนี้ยังไม่ได้รันกับ D1 จริงระหว่างการพัฒนา

- `npm test`: auth regression, สิทธิ์ผู้จัด/เจ้าของ, private document, การแก้ไข/ยืนยัน, idempotent submit และ concurrent review/edit, การเก็บบัญชีเดิมหลัง migration
- `npm run build`
- `npx wrangler deploy --dry-run --outdir .wrangler/deploy-check`

ทดสอบ Chromium ด้วยภาพเอกสารสังเคราะห์ใน D1 local แยกจากฐาน dev ปกติ (`LOCAL_D1_PATH`) ไม่สร้างบัญชีหรือเอกสารนักเรียนบน production
