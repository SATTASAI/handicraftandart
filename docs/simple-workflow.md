# ขั้นตอนใช้งานใหม่ — บัญชีครูเดียว

เอกสารนี้แทนขั้นตอนการยืนยันบัญชี/ทีมใน `verified-workflow.md` สำหรับรายการรุ่นใหม่ (`workflow_version=2`)

1. สมัครด้วยชื่อ โรงเรียน อีเมล และรหัสผ่าน ไม่เลือกบทบาทและไม่แนบบัตร
2. เลือกรายการแข่งขัน กรอกรายชื่อนักเรียน ชั้น/อายุ และครูผู้ฝึกซ้อม แล้วกดลงทะเบียนครั้งเดียว
3. ดูทีม วันเวลา และสถานที่ในหน้าแรก รอเข้าร่วมแข่งขัน ไม่ต้องรออนุมัติบัญชีหรือทีม

กรอกข้อมูลให้ตรงเกณฑ์รายการ เช่น จำนวนคน ชั้น อายุ ประเภทชาย/หญิง และลิงก์ผลงานที่จำเป็น ระบบตรวจจากฝั่งเซิร์ฟเวอร์ ครูเก็บฉบับร่างได้ และแก้ทีมที่ส่งแล้วได้จนหมดช่วงแก้ไข โดยไม่ต้องส่งให้แอดมินตรวจซ้ำ

## หน้าที่กรรมการ

ครูทุกบัญชีรับงานกรรมการได้ ผู้จัดมอบหมายรายบุคคลหรือใช้อัตโนมัติ ไม่ต้องเปลี่ยนบทบาทบัญชี ครูยังลงทะเบียนทีมได้เช่นเดิม แต่ห้ามตัดสินทั้งรายการที่มีทีมโรงเรียนตัวเองเข้าร่วม รวมถึงการเรียก API โดยตรง หากโรงเรียนส่งทีมเข้ารายการที่เคยมอบหมายให้ครูโรงเรียนนั้น ระบบถอนการมอบหมายที่ขัดกัน

ผู้จัดตั้งช่วงลงทะเบียน/แก้ไขในเวลา Bangkok ได้ หากยังไม่ตั้งช่วงเวลา ใช้เปิด/ปิดรับสมัครรายรายการ เมื่อปิดรับสมัครจะปิดการแก้ไขและเปิดให้กรรมการลงคะแนน กรรมการบันทึกร่างคะแนนได้และตรวจทานก่อนส่งผลขั้นสุดท้าย คะแนนขั้นสุดท้ายแก้ไม่ได้ เมื่อกรรมการที่ไม่มีผลประโยชน์ทับซ้อนส่งครบทุกทีม ระบบประกาศผล จัดอันดับ และเปิดดาวน์โหลดประกาศนียบัตรตามเดิม

## ย้ายระบบเดิม

สำรอง D1 ก่อนดำเนินการจริง แล้วใช้ `npm run db:remote` เพื่อรัน migration `0010_simple_teacher_workflow.sql` ก่อน deploy โค้ดนี้ Migration ไม่ลบบัญชี เอกสารเดิม ทีม หรือคะแนน บัญชีที่เคยรอตรวจเปิดใช้งานได้ทันที บัญชีที่ถูกปฏิเสธยังไม่เปิดใช้งานอัตโนมัติ รายการที่ประกาศผลแล้วหรือมีคะแนนขั้นสุดท้ายคงขั้นตอนเดิมเพื่อรักษาผลตัดสิน รายการที่ยังไม่ถึงขั้นนั้นเปลี่ยนเป็นรุ่น 2 ทีมที่มีสิทธิ์เข้าร่วมถือว่าลงทะเบียนเรียบร้อย

การสร้างฉบับใหม่จากรายการเก่าใช้ขั้นตอนรุ่น 2 ต้องรัน migration 0010 ก่อนเปิดใช้หน้าเว็บใหม่ `/api/health` จะแสดง release `simple-teacher-workflow-2569`

## ตรวจสอบ

- `npm test`: การทดสอบระบบใหม่และ regression ของระบบเดิม การทดสอบประวัติรุ่นเดิมหยุด migrations ก่อน 0010 โดยตั้งใจ
- `npm run build && npm run test:sites`
- `npx wrangler deploy --dry-run --outdir .wrangler/deploy-check`

คง DEMO_MODE=true จนผู้จัดยืนยันวัน เกณฑ์ และข้อมูลออกประกาศนียบัตรจริง การเปลี่ยนครั้งนี้ไม่ได้ deploy หรือแก้ฐานข้อมูล production

## Deploy อัตโนมัติจาก GitHub

Cloudflare Workers Builds ที่เชื่อม branch `main` และใช้ build command `npm ci && npm run build` จะรัน `prebuild` อัตโนมัติ: บันทึก D1 Time Travel bookmark ลง build log แล้วใช้ migrations กับ remote D1 ก่อน build/deploy หาก checkpoint หรือ migration ล้มเหลว build จะหยุด ไม่อัปโหลดโค้ดที่ต้องใช้ schema ใหม่ ต้องให้ token ของ Cloudflare build มีสิทธิ์ D1 ด้วย การ build ในเครื่อง, GitHub checks และ branch preview ไม่รัน remote migrations

การ push ยืนยันเพียงว่า GitHub รับโค้ดแล้ว ต้องตรวจ Cloudflare build log และ `/api/health` เพื่อยืนยันว่า deploy สำเร็จ
